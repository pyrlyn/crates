# mcp-client-host — completed tasks

### T1. Extract the MCP client host from cox

Moved the client half of cox's `cox-mcp` crate (aulo T1.12) onto rmcp 3.x with no behaviour change and no dependency on any cox crate. `discovery`: config, `.mcp.json` and `~/.claude.json` merged by precedence, `${VAR}` / `${VAR:-default}` expansion (lookup injectable through `discover_with`), plugin servers that any other source shadows, a broken file as a notice that names it. `client`: `connect_all` turns a server that fails, times out or needs a login nobody can run into a notice and keeps going; stdio servers get a cleared environment plus an allowlist, HTTP servers go through rmcp's `AuthClient`. `auth`: the `Secrets` store trait, `Memory`, the authorization-code flow with PKCE over a loopback redirect, the shell-free URL opener, the credential status report; `keyring` (feature `keyring`): the OS keyring store under a host-chosen service name and off-switch variable. `elicit`: schema to ordered fields, typed answers, review step, consented URL opening, the asker channel. `tool`: `McpTool` with a neutral `ToolSpec`/`ToolOutput`/`CallError`, namespaced `mcp__<server>__<tool>`, deferred, risk lowered only by `readOnlyHint`. cox types are replaced by `ServerConfig`, `Host` (secrets, prompt, asker, opener, app name, login command, child environment allowlist) and the `tool` types. Left in cox: the MCP server side (`server.rs`). Check: `cargo test -p mcp-client-host --all-features` (44 tests, including the fail-open and discovery tests and the OAuth 401-to-token contract test), `cargo clippy -p mcp-client-host --all-targets --all-features -- -D warnings`, `cargo fmt --all --check` and `cargo build --workspace` green on Rust 1.99.
