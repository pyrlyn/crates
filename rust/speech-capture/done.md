# speech-capture — completed tasks

### T1. Extract microphone capture and resampling from cox and runa

Merged cox's `crates/cox-voice` capture (aulo task T1.13) with runa's `crates/runa-media` decode, resample and energy VAD: `Recorder` and `input_device` (cpal default device, downmix, FFT resample to 16 kHz), `decode_audio` with `AudioProbe` and `pcm_sha256` (hound for wav, symphonia for the rest), `resample_mono` (sinc), `pcm_to_wav_bytes` and `energy_vad`. whisper.cpp transcription (`Transcriber`, `TranscribeError`) sits behind the `whisper` feature, off by default. Types are neutral (one `Error` enum), with no cox or runa dependency. Behaviour is unchanged except that the `cpal` callback no longer locks a `Mutex` or allocates a `Vec` as cox's did: it writes into a fixed-size `ringbuf` ring sized to the same length cap (the first `max` of audio is kept, the rest is dropped) and counts dropped samples in `Recorder::overflowed_samples`; a failed resample at `Recorder::stop` is `Error::Resample` instead of cox's `VoiceError::Stream`, error texts say "this program" instead of "this terminal", and the runa WAV fixtures became tone files the tests write themselves. Left in runa: `wav_base64`, model download, ASR engine, WER, video and preprocessing. Check: `cargo test -p speech-capture`, `cargo clippy -p speech-capture --all-targets -- -D warnings` green.

### T4. Streaming input with a named device

Added `InputDevice` (`find(Option<&str>)` by name or the default, `name`, `sample_rate_hz`, `start(sink)`) and the `InputStream` guard, which stops the stream on drop. The sink receives mono `f32` at the device rate from the audio thread in stack-sized chunks, with no lock and no allocation of its own; the `cpal` stream lives on its own thread because it is not `Send` on every platform. `Recorder` was rebuilt on it, so `src/input.rs` is the only place that opens a `cpal` stream; its behaviour is unchanged (same ring, same overflow count, same 16 kHz result). New `Error::DeviceNotFound`. New cargo feature `decode` (default on) gates `decode_audio` and symphonia, hound, sha2 and serde, so a caller that only captures can use `default-features = false`. Added for aulo's `aulo-audio` (T6.1). Check: `cargo test -p speech-capture` (also `--no-default-features`), `cargo clippy -p speech-capture --all-targets -- -D warnings` green.
