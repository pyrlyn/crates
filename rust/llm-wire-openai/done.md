# llm-wire-openai — completed tasks

### T1.3. Extract llm-wire-openai: Chat and Responses wires

Copied from cox's `cox-provider-openai` so aulo can share the wires; cox is untouched. Moved: `chat` (`build_body`, `OpenAiChatStream`, `OpenAiChatProvider`), `responses` (`build_body`, `OpenAiResponsesStream`, `OpenAiResponsesProvider`) and `wire` (the `async-openai` Responses type re-exports), with their unit tests, the 13 insta snapshots and the recorded SSE fixtures from cox's `fixtures/openai-chat` and `fixtures/openai-responses`. `ProviderError`, `ProviderEvent`, `Provider` and the request types now come from `llm-wire`, and the credential, retry and SSE plumbing from `llm-http`. Differences from cox: the `Transport` and `ProviderModel` config types and the `Capabilities` flags live in `config` (cox keeps them in `cox-protocol` and `cox-models`, which carry its whole config schema and catalog), `ProviderModel` drops the fields the wires never read (`display_name`, `efforts`), and `Capabilities::chat_effort` replaces `cox_models::effort_for`: the Chat wire sends `reasoning_effort` only when the model declares it, and the Responses wire always sends the effort. Request bodies, event mapping and retry behaviour are unchanged, and the snapshots pass byte for byte. Check: `cargo test -p llm-wire-openai` (57 tests, no external network; the client tests use a local `wiremock` server), `cargo clippy -p llm-wire-openai --all-targets -- -D warnings`, `cargo fmt --all --check` and `cargo build --workspace` green.

### T1.3.1. Use the shared model, effort and transport types

Aulo follow-up to T1.3. The `config` module is gone: `Transport` comes from `llm-http`, `ProviderModel` and `Capabilities` from `llm-wire` (`ProviderModel` regains the `display_name` and `efforts` fields the wires never read). `Capabilities::chat_effort` is replaced by `llm_wire::effort_for`, which the Chat wire calls with `Api::Chat` and the Responses wire with `Api::Responses` (always sends the effort).
