# llm-wire-anthropic — completed tasks

### T1. Extract the Anthropic Messages wire from cox

Copied from cox's `cox-provider-anthropic` so aulo can share the wire; cox is untouched. Moved: `request` (`build_body`, `BuildCfg`, cache breakpoint placement, key order, thinking replay), `stream` (`AnthropicStream`), `wire` and `build.rs` (typify over the vendored OpenAPI snapshot, `schema/`, byte-identical), the client (`AnthropicProvider`, `CacheTtl`, headers, workspace id, `Provider` impl), the six recorded SSE bodies from cox's `fixtures/anthropic` and the insta snapshots, with their unit and wiremock tests. Differences from cox: `ProviderError`, `ProviderEvent`, `Request`, `Provider` and the rest come from `llm-wire`, and credentials, retry and SSE framing from `llm-http`. `AnthropicProvider::new` takes the keyring service and switch variable (cox hard-coded `cox` and `COX_KEYRING`). `Transport` (cox's `cox_protocol::config::Transport`) is a local struct because `llm-wire` does not carry it. cox-models' `effort_for` (the Anthropic arm always sends the effort) and `supports_adaptive_thinking` are inlined in `request`, because this crate must not depend on a cox crate. The tests inject the environment instead of calling `set_var` (this crate forbids `unsafe`); the one that checked env-over-keyring precedence is covered by `llm-http`, and the renamed-key-env test reads `PATH`. Fixtures load from the crate's own `fixtures/`. `missing_docs` is on (cox allowed it away). Check: `cargo test -p llm-wire-anthropic` (48 tests, no network beyond loopback `wiremock`), `cargo clippy -p llm-wire-anthropic --all-targets -- -D warnings`, `cargo fmt --all --check` and `cargo build --workspace` green.
