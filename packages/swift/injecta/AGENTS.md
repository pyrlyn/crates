## Using Injecta (for agents writing application code)

The full guide is `GUIDE.md` (also in `llms-full.txt`). The short version:

1. Put `@Injectable` on every concrete type the container should build. Its initializer's
   argument labels are the entries it needs. If it has several initializers, mark one `@Inject`.
2. Declare one `@Container final class` per lifetime: the app (composition root, next to `@main`)
   and one per scope (session, request, window). Mark it `Sendable` when every entry is Sendable;
   mark it `@MainActor` when it builds `@MainActor` types.
3. Entries:
   - `let name: Type` without a value: an input (values you already have: config, values that
     needed `async` or `throws`, the session a scope is for). It becomes an `init` parameter.
   - `@Singleton var name: Type`: one shared value per container, built on first read.
   - `@Transient var name: Type`: a new value on every read.
   - `@Provides(.singleton | .transient | .eagerSingleton) func makeName(label: T, ...) -> Type`:
     for protocol types (`any P`), types from other modules, generic types, custom construction.
   - `@Forward var name: Type` in a child container: the parent's entry (`let parent: AppGraph`).
   - A `Lazy<T>` or `() -> T` parameter reads entry `T` later. It is not a cycle edge and it does
     not capture a transient. `() -> T` is a new value per call; `Lazy<T>` is one value, on first
     `.value`. Do not force it from the initializer that received it.
4. Attach `InjectaCheckPlugin` to the target that declares the container. Without it, a debug
   build traps on `init` with `missingPluginMessage` (the setup step); a release build fails to
   compile. A hand-written `extension Container: Type.Needs {}` is the other fix.
5. Read entries as properties: `graph.repo`. In tests and previews, pass `Overrides` to `init`.

Hard rules:

- Never store the container inside a service, and never read it from a global; inject entries.
- Never make an `async` or throwing provider; build the value first and pass it as an input.
- When the compiler says `'x' needs 'y', but the container has no entry named 'y'`, add the entry
  `y` (input, provider, or `@Singleton`). Do not add a default value or an optional to silence it.
- A `dependency cycle: a -> b -> a` is a design error. Extract the shared part into a third entry.
- Do not write `extension Container: Type.Needs {}` by hand when the plugin is attached: the
  plugin generates it, and a second one is a redundant-conformance error.
- One container type per lifetime. Tests use `Overrides`, not a test container.

## Changing Injecta (for agents working on this package)

- Layout: `Sources/InjectaGraph` (graph model and checks, no dependencies), `Sources/InjectaSyntax`
  (reads declarations into the model; shared by macros and checker; the macro target compiles
  it through the `Sources/InjectaMacros/Reader` symlink, so never add a target dependency on it
  from the macro), `Sources/InjectaMacros`
  (`@Injectable`, `@Inject`, `@Container`, `@Singleton`, `@Transient`, `@Provides`, `@Forward`),
  `Sources/Injecta` (runtime: `Once`, protocols, macro declarations), `Sources/injecta-check` and
  `Plugins/InjectaCheckPlugin` (whole-target checks and generated conformances). `Benchmarks/` is a
  separate package and never a dependency of the library.
- A rule lives once: graph rules in `InjectaGraph`, syntax rules in `InjectaSyntax`. The macros
  and the checker only translate problems into diagnostics.
- The resolve path stays free of locks, dictionaries, task-locals and allocation beyond the user's
  own initializers. A change to generated getters or to `Once` needs a `Benchmarks/measure.sh` run
  and the numbers in the commit message.
- Every misuse a macro can catch gets a test in `Tests/InjectaMacrosTests` with the exact message,
  and the message says how to fix it.
- Docs have one source: `GUIDE.md` and this file. `llms.txt` and `llms-full.txt` are generated by
  `INJECTA_BLESS=1 swift test --filter DocsTests`; the same test fails when they are stale.
- Before calling work done: `swift build`, `swift test` (all targets), and for performance work
  `Benchmarks/measure.sh`.
- Conventional Commits in English. The human is the only author: no `Co-Authored-By` or
  "Generated with" lines.
